# 比赛要求与当前实现状态

## 来源与适用题目

本文根据用户提供的《大模型驱动的复杂系统自检自愈与自优化挑战赛（北航—华为可靠性创新实验室）》通知整理，重点核对 **第 3 页 A 题**和**第 6 页提交流程**。这是该版本通知的整理，不代表赛事后续变更。

本仓库对应 **A 题：基于大模型 Agent 的器件故障预测算法及自动化调优**。B 题有不同任务，本仓库不宣称实现 B 题。

## A 题任务

针对时序数据、文本事件等器件故障数据，设计通用故障预测算法，以及由大模型 Agent 驱动的自动调优和模型迭代方法。根据预测结果和误告、漏告分析形成反馈闭环，持续优化到预设目标，并将流程沉淀为标准化规范或 Skill。

要求覆盖参数自适应搜索与调优、模型结构优化等内容，明确预测性能、推理时延、模型参数量与复杂度等评价指标。使用内存、硬盘、光放大器等实际数据进行验证，评价方法的有效性与跨场景泛化。

## 评审维度

1. **预测性能提升**：准确率、召回率、误告、漏告等指标及其改善。
2. **模型及调优成本**：模型参数量、模型复杂度、Token 消耗量；题目描述还明确要求关注预测时延。
3. **自动执行能力**：无需人工介入的步骤比例、全流程自动执行比例，以及达到预设目标所需调优轮次和时间。
4. **泛化能力**：方法在内存、硬盘、光放大器等数据上的效果一致性和跨场景迁移能力。

“准确率”与 precision（精确率）不是同一个指标。仓库现有 precision/recall/F1 不能被标注为已实现全部 Accuracy 要求。当前设备评分中，故障设备仅在无效窗口报警时可能同时计 FP 和 FN；如要补充 Accuracy，须先给出一致的互斥样本类别和分母定义。

## 要求对照表

| 要求 | 当前证据/实现 | 状态与待办 |
|---|---|---|
| 大模型 Agent 调优闭环 | 三角色、受约束动作、训练执行、诊断反馈、预算和持久化 | 已实现工程闭环； |
| 参数搜索与模型迭代 | 参数对照、设备权重、特征程序、可选门控/独立分支 | 已实现受约束范围；不是任意模型结构搜索 |
| 误报、漏报分析 | 高分对比、漏报对比、覆盖分解、配对变化 | 已实现 |
| Precision、Recall、F1、TP/FP/FN | 固定设备级评价与结果文件 | 已实现；每个具体任务需说明评分协议 |
| 无人工介入比例/全流程自动比例 | 有事件和调用记录 | 自动化分母、人工介入标记及比例统计待补充 |
| 预设目标及达标轮数/时间 | 有预算和实验记录 | 预设指标目标、首次达标事件及统计待补充 |
| 标准化 Skill/Spec | 包内 skill、共享方法、角色提示和执行约束 | 已提供，并实际注入模型调用 |
| 多器件泛化与迁移验证 | 有内存/硬盘合成集成测试和 TypeA 真实样本执行核验 | 完整真实跨域效果、TypeB/光放大器迁移待验证 |
| 严格时间外推评估 | 目前是 TRAIN 内设备分组 CV 加时间保留窗口 | CV 中其他设备可能有同时段训练数据；严格时间外推未实现 |
| 测试报告与 session 数据 | 仓库含脱敏验证摘要；实际运行会生成 session | 正式比赛需另外整理有权限的真实实验 session 和结果材料 |
