# 内存 TypeA · v3.2 最终结果

代码：提交 `8ebafc8`（仓库根目录代码与 [`session/code_seal.json`](session/code_seal.json) 逐字节一致）。运行时间：2026-10-29，13 组实验共 5.1 小时，全部自动完成。

## 结论

Agent 闭环在 13 组实验中采纳了 **trial_008**：特征 Agent 根据漏报诊断写的 4 个因果特征 + 按设备加权。

| 评估 | 模型 | 工作点 | TP | FP | FN | 精确率 | 召回率 | **F1** |
|---|---|---|---:|---:|---:|---:|---:|---:|
| 历史 TEST（101 台故障） | 基线 trial_001 | CV OOF（部署） | 20 | 183 | 81 | 9.85% | 19.80% | 13.16% |
| | 基线 trial_001 | 选择窗口 | 24 | 170 | 77 | 12.37% | 23.76% | 16.27% |
| | **trial_008** | **CV OOF（部署）** | **27** | **139** | **74** | **16.27%** | **26.73%** | **20.22%** |
| | trial_008 | 选择窗口 | 19 | 76 | 82 | 20.00% | 18.81% | 19.39% |
| 确认窗口（40 台故障） | 基线 trial_001 | CV OOF（部署） | 8 | 163 | 32 | | | 7.6% |
| | 基线 trial_001 | 选择窗口 | 11 | 144 | 29 | | | 11.3% |
| | **trial_008** | **CV OOF（部署）** | **12** | **103** | **28** | | | **15.5%** |
| | trial_008 | 选择窗口 | 9 | 61 | 31 | | | 16.4% |

- 无论用哪种工作点，trial_008 在确认窗口和历史 TEST 上都优于基线；
- CV OOF 工作点对 trial_008 有帮助，对基线却更差，所以**两种工作点各有优劣，不是绝对更好**；
- 历史 TEST 时间段在项目早期被查看过，这些成绩是回顾性评估，不是新的独立盲测。确认窗口在搜索中没有使用过。

### 被采纳的实验

trial_008 的采纳证据（[`cv_comparison_best.json`](session/trials/trial_008/attempt_01/cv_comparison_best.json)）：和基线相比，CV F1 +2.10 个百分点，P(更好) = 0.932，CV 中新增命中 26 台、丢失命中 15 台。按 v3.1 的旧规则（95% 区间下界 > 0），它的区间 [-0.62, +4.81] 会被拒绝。

特征 Agent 生成的特征（[`transform.py`](session/feature_programs/0e508b9d920307b71958129be58310de13b729cd3afa4ad1e04b359506764c52/transform.py)），全部基于原始日志特征：

| 特征 | 含义 |
|---|---|
| `fe_recent_new_col_share` | 最近 7 天新出现的出错列占所有出错列的比例 |
| `fe_recent_new_pattern_rate` | 最近 7 天新出现的错误模式数 / 累计事件数 |
| `fe_top_cell_dispersion` | 1 − 最集中单元的错误占比（错误越分散，值越大） |
| `fe_spread_error_intensity` | 分散度 × log(1 + 6 小时内 DQ 错误 + 突发错误) |
