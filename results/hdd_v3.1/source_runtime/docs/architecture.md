# 框架与模块说明

## 设计目标

将器件故障预测组织成可重复、可诊断、可停止的实验闭环：根据误报、漏报和覆盖证据提出假设，通过受控实验判断是否值得采纳。大模型负责提出计划和受约束的特征程序，统计口径和数据隔离由普通程序执行。

| `sample_builder.py`、`training_selector.py` | 合法训练标签、成熟度过滤、冻结采样和基础权重 |

| `crossval.py`、`comparison.py` | 设备分组 CV、同评价身份对照、配对统计 |

## 三种不同的实验问题

### 减少误报

分析高分真故障与高分正常设备的差异，尝试因果特征、设备权重或允许的重排。高分子集诊断不能代表所有漏报设备。

### 找回漏报

先排查是否有足够历史、及时预测机会和有效分数，再比较低分故障与正常设备的表示。允许有明确理由的有限特征探索；独立补充分支能够影响父模型低分样本，但也可能增加误报。

### 排除执行问题

训练报错不等于模型性能差。普通错误记录为失败并保存原因；明确资源故障暂停等待修复。失败结果不被写成有效性能证据。恢复不重置探索名额或调用预算。

## 设备权重与冻结采样

冻结采样决定哪些 TRAIN 行被保留，并提供补偿被抽样行的权重。`base_weight=device` 不更换这些行：将每个训练设备内部的保留权重除以该设备保留权重的总和。设备内相对采样补偿保留，设备总基础权重为 1，再依据归一化后的类别质量计算类别权重。

CV 先排除留出设备，再进行训练设备的归一化。全局负例采样补偿总质量在设备归一化之前核验；设备归一化之后不再要求等于原始负例行数。

## 数据边界

1. 特征只能使用在预测时刻已可用的历史信息；字段名相似不等于单位和物理含义相同。
2. 故障工单和随访规则用于合法标签和评价队列，不能把未知随访直接判成正常。
3. 评价规则、设备队列和提前量在会话中固定；改变它们应建立新实验身份。
4. 新数据集使用独立会话。跨数据集默认仅复用超参数候选和语义经验，不能默默复制拟合树或阈值。
5. 原始文件可能同时包含多个时期。构建器为确定时间边界可能读取全文件；这不代表 TEST 特征或标签被允许用于学习。需要字节级隔离时，应提前物理拆分原始文件。

## 泛化性的不同层次

- **接口兼容**：映射、训练、诊断在不同输入格式或设备域上可运行。
- **框架泛化**：使用相同实验方法，在各自独立划分上改善多个设备域的表现。
- **模型迁移**：冻结或适配某一域的拟合模型，再评价另一域。

当前证据支持部分接口和执行路径的兼容性；没有据此宣称普遍跨域性能提升。TypeA、TypeB 或光网络的迁移实验需要专门设计特征对齐、训练边界和保留测试集。
